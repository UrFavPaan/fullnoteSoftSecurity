Handling Input
• Handling input is a critical aspect of
software security.
• Input from users, other systems, or external
sources can contain malicious code or data
that can compromise the security of the
software.
• Therefore, it is essential to carefully handle
input and ensure that it is validated and
processed securely to prevent
vulnerabilities and attacks.

Classification Inputs:
• Before processing input, it is essential to classify it into different
categories based on its source, format, and content.
• Inputs can be classified into two categories: trusted and untrusted.
• Trusted inputs come from reliable sources, such as internal systems or
trusted users,
• While untrusted inputs come from untrusted or unknown sources, such
as user input from the web or other external systems.

Validate Input
• Validating input is an essential step in ensuring software security.
• Input validation refers to the process of checking the input for validity and
verifying that it meets specific requirements or constraints.
• Objectives: (1) validating that user input contains only alphanumeric
characters, (2) verifying that input values are within acceptable ranges, and (3)
validating that input data does not contain malicious code or characters that
can lead to SQL injection or other types of attacks.
• Input validation can be performed using different techniques, such as input
filtering (Accept only the good stuff), input sanitization (clean what’s dirty), and
input normalization (make it consistent).

Input validation strategies: Syntactical (I)
• Input validation should be applied on both syntactical and semantic levels.
• Syntactical validation involves checking the input data for compliance with a
specific format or syntax.
• For example, if a user is asked to input an email address, the input should be
validated to ensure that it contains the "@" symbol and ends with a valid top-
level domain (TLD) like ".com", ".net", or ".org".
• The domain part contains only letters, numbers, hyphens (-) and periods (.).
• The email address is a reasonable length:
• The local part (before the @) should be no more than 63 characters.
• The total length should be no more than 254 characters.

Input validation strategies: Semantic (I)
• Semantic validation, on the other hand, involves checking the input data
for compliance with the application's business rules and logic.
• This ensures that the input data makes sense and valid in the context of
the application.
• For example, if a user is asked to input their age, the input should be
validated to ensure that it falls within an acceptable range for the
application, such as between 18 and 100 years old.
• For example, to ensure email address is correct and legitimate: Send an
email to the user and require that they click a link in the email or enter a
code that has been sent to them.

Prevention Measures (Handle input securely)
• There are several prevention measures can be applied to handle input securely.
(1) Another measure is to use prepared statements or parameterized queries to
prevent SQL injection attacks.
(2) These include input encoding, which involves converting input data into a
secure format, such as HTML encoding, to prevent SQL Injection & cross-site
scripting (XSS) attacks.
(3) Input data should also be checked for buffer overflows, which can be avoided
by disallowed any input value is larger than the allocated buffer size, leading
to memory corruption and potentially remote code execution.
(4) Additionally, implementing access controls and privilege management can
limit the impact of input-related attacks by restricting user access to critical
system resources.

SQL Injection (II)
• When an attacker can modify an SQL statement, the statement will
execute with the same rights as the application user; when using the
SQL server to execute commands that interact with the operating
system, the process will run with the same permissions as the component
that executed the command (e.g. database server, application server, or
Web server), which is often highly privileged.
• SQL injection has probably existed since SQL databases were first
connected to Web applications.

Prevent Sensitive Data Exposure
• Prevent storage of unwanted data
• Don’t store any sensitive information that is not required.
• Classify the data processed, stored, or transmitted by our application.
• Identify which data is sensitive according to privacy laws or business needs.
• Encrypt all sensitive data stored
• Encrypt all sensitive data that is stored by our application.
• Use strong and updated standard algorithms, protocols, and keys to protect it.

Summary
• Proper input handling is essential to prevent software vulnerabilities and
security breaches.
• Input validation (both syntactic and semantic) is critical for ensuring data
integrity and application logic.
• Best practices such as input filtering, sanitization, and encoding help
mitigate risks like SQL injection and XSS.
• Securely handling sensitive data (e.g., passwords and credit cards) requires
rest and transit encryption.
• Prevention strategies like prepared statements, TLS, and access control
should be implemented to protect systems.
