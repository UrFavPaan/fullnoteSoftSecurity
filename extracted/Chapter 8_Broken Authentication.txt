What Is Broken Authentication? (I)
A broken authentication refers to the vulnerabilities or weaknesses inherent in an
online platform or application that allows hackers to bypass the login security and
gain access to all the privileges owned by the hacked user.
There are two main categories of vulnerabilities causes broken authentication:

Basically, a session ID is created and assigned to a user whenever they log in to a site.

(1) Session Management Vulnerabilities (II)
If an attacker can get a hold of a user’s session ID while they are logged in, then that

impersonate the user and perform actions within the website.

(2) Credential Management Vulnerabilities
▪ The theft of usernames and passwords is the first thing that usually comes to mind
when we think of attackers gaining unauthorized access to an application. Proper
credential management is critical for the users of any system, and applications
themselves must take all possible precautions when dealing with passwords and their
creation.
▪ In this case, broken authentication occurs when a site fails to protect its users from
attackers that try to gain access via hacked or stolen passwords.

(3) Session Hijacking (I)
Session hijacking is an attack where a user session is taken over by an attacker. A
session starts when you log into a service, for example your banking application,
and ends when you log out. The attack relies on the attacker’s knowledge of your
session cookie, so it is also called cookie hijacking or cookie side-jacking. Although
any computer session could be hijacked, session hijacking most commonly applies
to browser sessions and web applications.

(4) Session ID URL (I)
When a user logs in to a website, the server generates a unique session ID and stores it
in a cookie on the user's browser. This session ID is then appended to the end of the
URL as a parameter, allowing the server to associate subsequent requests from the
user with the correct session.

(5) Phishing Attacks (I)
A phishing attack is a category of cyber attack in which malicious actors send messages

causing them to perform actions like installing malicious files, clicking harmful links, or
divulging sensitive information such as account credentials. This message can be sent to
the target via emails, messaging applications, or even SMS services.

(1) Secure Password Storage (I)
Secure password storage is an important aspect of web application security, as
passwords are often the first line of defense against unauthorized access. There
are several vulnerabilities that can arise when passwords are not stored securely,
including:
a. Plain-text password storage: This is the most basic vulnerability, where
passwords are stored in plain text format, which can be easily read and accessed
by anyone with access to the storage location.

--- Page 26 ---
By:

(1) Secure Password Storage (II)
b. Weak password hashing: Passwords
are often hashed before being stored in
a database, but if the hashing algorithm
is weak, it can be vulnerable to attacks
like brute force or dictionary attacks.

c. Inadequate salt usage: Salting is the
process of adding a unique, random
value to each password before it is
hashed. If the salt is not unique or
random enough, it can make it easier for
attackers to crack passwords.

d. Vulnerable password recovery mechanisms: Password recovery mechanisms,
such as email password reset links, can be vulnerable to attacks if they are not
properly secured. For example, if an attacker gains access to a user's email
account, they can use the reset link to gain access to the user's account.
e. Insider attacks: Insiders with access to the password storage system can pose a
threat to password security. This includes employees or contractors who may
abuse their access or accidentally leak information.

(2) Don't Allow Weak Passwords (I)
You must require all users to achieve specific requirements when specifying their
passwords. For example, setting passwords to a particular length and requiring special
characters and letters as well as numbers helps prevent credential theft. Consequently,
your system will reject passwords that don't meet the requirements.

services.Configure<IdentityOptions>(options => {
// Password settings

options.Password.RequiredLength = 8;
options.Password.RequireNonAlphanumeric = true;
options.Password.RequireUppercase = true;
options.Password.RequireLowercase = true;
options.Password.RequiredUniqueChars = 6;
});

(4) Implement Protection of Breached Password
A breached password protection mechanism will lock the accounts of users whose
passwords have been compromised. In addition, we can configure this mechanism
to return access when users change their passwords. This way, we guarantee that
the users have a chance to prevent damage if attackers steal their passwords.

of this period depends on the type of application. For example, a streaming platform
might require a long period of inactivity, while a sensitive banking website should have a
short time limit.

bypassable, or sensitive information is stored or transmitted
in an insecure manner.
