What is access control?
• Access control (or authorization) is the application of constraints
on who (or what) can perform attempted actions or access
resources that they have requested.
• In the context of web applications, access control is dependent
on authentication and session management:

Vertical access controls I
• Vertical access controls refer to access controls that are
applied to different levels of an organization or system
hierarchy.
• This means that access controls are implemented at different
levels, and users are granted or denied access based on their
role or level of authority within the organization or system.

Horizontal access controls
• Horizontal access controls refer to access controls that are
applied across different users or entities at the same level
within an organization or system hierarchy.
• This means that access controls are implemented based on
specific attributes or characteristics of the user, rather than
their position or level of authority within the organization or
system.

Context-dependent access controls
• Context-dependent access controls are access controls that
are applied based on specific contextual factors, such as
location, time, device, or network.
• These controls take into consideration the specific
environment in which a user is accessing resources and
adjust access permissions accordingly.

Common Attacks: Access to Admin
Pages
• Administrative functions should be linked from an
administrator’s welcome page but not from a user’s welcome
page.

by browsing directly to the relevant admin URL.
• https://target.com/admin

Local File Inclusion (LFI)
LFI occurs when a web application allows a user to include a
local file, such as a configuration file or password file, by
specifying a path to the file in a parameter of the web request.
The attacker may use ".." to navigate up the directory structure
and access files outside of the application's root directory.

Remote File Inclusion (RFI)
RFI occurs when a web application includes a file from a
remote server specified in a parameter of the web request.
The attacker may craft a malicious URL that points to a file
hosted on their own server, which is then included by the
vulnerable application.

Common Attacks: Spoofing
Spoofing is a technique used by cyber criminals to deceive
individuals or computer systems by falsifying information to
appear as though it came from a trustworthy source.
This can include falsifying email addresses, IP addresses, or
websites to make them appear legitimate.
The goal of spoofing attacks is often to gain access to sensitive
information or to trick individuals into taking a specific action.

Real-World Scenarios: Insecure Direct
Object Reference (IDOR)
• Insecure Direct Object References (IDOR) occur
when an application provides direct access to
objects based on user-supplied input, such as an ID
or a key.
• As a result of this vulnerability, attackers can bypass
authorization and access resources in the system
directly, for example, database records or files.

Real-World Scenarios: Broken Object
Level Authorisation (BOLA)
• The logic behind Broken Object Level Authorisation (BOLA)
and IDOR are the same. Therefore, we can define BOLA as
“IDOR in APIs”.
• APIs tend to expose endpoints that handle object identifiers,
creating a wide attack surface Level Access Control issue.
Object-level authorization checks should be considered in
every function that accesses a data source using input from
the user.

Remediation Guidelines
• Access control vulnerabilities cannot be prevented by
applying a single formula or simple, ordinary and common
checks because; access rights, permissions, principles, and
other factors often vary due to the differences in context,
workflow, and purpose of the applications.

Authorization Security
• Do Not Rely on Obfuscation
• Deny Access by Default
• Single Application-Wide Mechanism (consistent for all
modules)
• Continuous Audit and Test Access Control
• Minimize CORS (Cross-Origin Resource Sharing) Usage
• Web page can only make requests to the same domain it was loaded from
(this is called the Same-Origin Policy).
