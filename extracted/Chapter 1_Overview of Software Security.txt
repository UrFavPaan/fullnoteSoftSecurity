• Software security is the idea of engineering
software so that it continues to function
correctly under malicious attack.
• Software Security aims to avoid security
vulnerabilities by addressing security from
the early stages of software development
life cycle.

What & Why is Software Security? (III)
Most software systems today are insecure and contain numerous flaws
and bugs that attackers exploit. There are different reasons for insecure
software, such as:
• Lack of education in secure methods.
• Lack of thought in the design process
• Lack of testing.
• Poor development environments.

Terminology (I)
• Defects are problems that deviates from the requirements and specification.
o Example: The requirement says the app must allow password of at least 8 characters, but the
app allows 5 characters.
• Bugs are implementation-level or coding errors that cause software to behave
incorrectly
o Example: The app crashes when click “Login” button.
• Flaws are weakness or imperfection in the design, architecture, or logic that may
lead to problems.
o Example: The app stores passwords in plain text instead of encrypted. This is a design flaw.
• Failures are the inability of the software to perform its required function.

Terminology (II)
• Risks capture the probability that a flaw or a bug will impact the
purpose of the software.
o Risk = probability (of what?) x impact
• Vulnerabilities are weaknesses or errors that an attacker can exploit.
o Either flaws in the design or flaws in the implementation.
o Design-level vulnerabilities are the hardest defects to handle.

3- Architectural Risk Analysis (III)
• Attack Resistance Analysis:
• It captures the check-list like approach to the risk analysis taken in Microsoft

2. Map attack patterns using either the results of abuse case development or a list of

4. Understand and demonstrate the viability of these known attacks.

4- Risk-Based Security Testing (I)
• Testers must follow:
• Risk-based approach:
• Grounded in both system's architectural reality and the attacker's mindset.
• Focused on areas of code where an attack is likely to succeed.
• Different from Penetration Testing:
• Level of approach: Inside-out approach.
• Timing of testing: Before the software is complete.
• Should start prior to system integration.
• Risk analysts should identify and rank risks.

Quality vs Secure Code (I)
• Quality Code
• Focus: Functionality, performance, usability, maintainability
• Goal: Meets user requirements and performs tasks efficiently
• Examples:
• - Fewer bugs and crashes
• - Well-documented, easy to maintain
• - Fast and reliable performance

Quality vs Secure Code (II)
Secure Code
• Focus: Protection against threats, vulnerabilities, and attacks
• Goal: Ensures confidentiality, integrity, and availability of data
• Examples:
• - Proper input validation
• - Safe authentication & access control
• - Resilience against SQL injection, buffer overflows, etc.

Summary
▪ Most software systems today are insecure and contain numerous flaws and bugs
that attackers exploit.
▪ Defects, Bugs, Flaws, Risks, and vulnerabilities are the terms used in software.
▪ There are three pillars in software security: risk management, touchpoints, and
knowledge.
▪ Threat modeling is a structured process used in cybersecurity to identify, assess,
and mitigate security risks within a system, application, or network.
